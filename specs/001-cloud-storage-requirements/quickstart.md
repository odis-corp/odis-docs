# Quickstart: проверка облачного хранилища

**Feature**: `specs/001-cloud-storage-requirements` | **Date**: 2026-11-06

Набор сценариев, по которым проверяется, что реализация соответствует спецификации. Каждый сценарий привязан к критерию успеха (`SC-*`) и требованию (`FR-*`). Сценарии выполняются на одном узле, развёрнутом через `deploy/docker-compose.yml`.

---

## 0. Подготовка

```bash
# 1. Поднять окружение
docker compose -f deploy/docker-compose.yml up -d

# 2. Дождаться готовности
curl -fsS http://localhost:8080/healthz
# → {"status":"ok","db":"ok"}

# 3. Создать администратора (первый запуск)
docker compose -f deploy/docker-compose.yml exec server \
  ./server admin create --email admin@example.test --name "Admin"

# 4. Создать двух пользователей и группу
curl -X POST http://localhost:8080/api/v1/admin/users \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -d '{"email":"alice@example.test","display_name":"Alice"}'
curl -X POST http://localhost:8080/api/v1/admin/users \
  -H "Authorization: Bearer $ADMIN_TOKEN" \
  -d '{"email":"bob@example.test","display_name":"Bob"}'
```

Ожидаемо: `healthz` отвечает `ok`, пользователи созданы, в журнале (`/admin/audit`) появились записи о создании.

## 1. Базовое хранение (SC-001, FR-009…FR-016)

```bash
# Загрузить файл 10 МБ
head -c 10485760 /dev/urandom > /tmp/sample.bin
curl -X POST http://localhost:8080/api/v1/uploads \
  -H "Authorization: Bearer $ALICE_TOKEN" \
  -d '{"parent_id":"'$ROOT'","name":"sample.bin","size":10485760}'
# → 201 { "id": "...", "upload_url": "...", "offset": 0 }

# Передать содержимое (одним или несколькими PATCH)
curl -X PATCH "$UPLOAD_URL" \
  -H "Upload-Offset: 0" \
  -H "Content-Type: application/offset+octet-stream" \
  --data-binary @/tmp/sample.bin

# Скачать и сравнить
curl -fsS "http://localhost:8080/api/v1/nodes/$NODE/content" -o /tmp/back.bin
sha256sum /tmp/sample.bin /tmp/back.bin
```

**Ожидаемо**: хеши совпадают; файл виден в листинге; размер в сводке квоты увеличился ровно на 10 МБ.

**Проверка краевого случая «файл ещё не готов»**: начать `PATCH` и, не завершая, запросить `GET /nodes/{id}/content`. Ожидаемо: `409`/`425` с понятным сообщением, но **не** частичное содержимое.

## 2. Права и группы (SC-004, FR-001…FR-008)

```bash
# Alice создаёт папку и делится с Bob на просмотр
curl -X POST .../nodes -d '{"parent_id":"'$ROOT'","name":"Shared"}'
curl -X POST .../nodes/$SHARED/shares \
  -d '{"grantee_user_id":"'$BOB'","level":"view"}'

# Bob пытается удалить
curl -X DELETE .../nodes/$SHARED -H "Authorization: Bearer $BOB_TOKEN"
# → 403 forbidden
```

**Ожидаемо**: Bob видит папку, но не может изменить; попытка доступа к чужой папке без выдачи возвращает `404` (не `403`), чтобы не раскрывать существование.

**Проверка группы**: добавить Bob в группу, выдать доступ группе, исключить Bob — доступ должен исчезнуть.

## 3. Публичные ссылки (SC-006, FR-036…FR-043)

```bash
# Ссылка с паролем и сроком
curl -X POST .../nodes/$FILE/links \
  -d '{"kind":"view","password":"s3cret","expires_at":"2026-11-07T00:00:00Z"}'
# → 201 { "url": "http://localhost:8080/public/<token>" }

# Без пароля
curl -i "http://localhost:8080/public/<token>"
# → 401 password_required

# С паролем
curl -fsS "http://localhost:8080/public/<token>?password=s3cret"
# → 200 метаданные

# Отзыв
curl -X POST .../links/$LINK/revoke
curl -i "http://localhost:8080/public/<token>?password=s3cret"
# → 410
```

**Ожидаемо**: после отзыва — `410` немедленно; ссылка на папку не раскрывает соседние объекты; ссылка на загрузку не позволяет читать содержимое папки.

## 4. Версии и корзина (SC-005, FR-027…FR-035)

```bash
# Три версии файла
for i in 1 2 3; do
  echo "version $i" > /tmp/v.txt
  # загрузить как новую версию того же узла
done

curl .../nodes/$FILE/versions
# → 3 версии с автором и временем

# Восстановить первую
curl -X POST .../nodes/$FILE/versions/$V1/restore
curl .../nodes/$FILE/content
# → "version 1"

# Удалить и восстановить из корзины
curl -X DELETE .../nodes/$FILE
curl -X POST .../nodes/$FILE/restore
```

**Ожидаемо**: восстановление версии не удаляет остальные; восстановление из корзины возвращает на исходное место; при занятом месте создаётся копия, а не перезапись.

## 5. Синхронизация и конфликты (SC-003, FR-044…FR-052)

Сценарий требует двух устройств (два экземпляра `sync-agent` с разными каталогами).

```bash
# Устройство A и B синхронизируют одну папку
sync-agent --server http://localhost:8080 --token $ALICE_TOKEN --dir /tmp/devA
sync-agent --server http://localhost:8080 --token $ALICE_TOKEN --dir /tmp/devB

# 1. Изменение на A доезжает до B
echo "from A" > /tmp/devA/doc.txt
# дождаться синхронизации
cat /tmp/devB/doc.txt   # → "from A"

# 2. Конфликт: оба офлайн
# остановить оба агента
echo "A offline" > /tmp/devA/doc.txt
echo "B offline" > /tmp/devB/doc.txt
# запустить оба
```

**Ожидаемо**:
- существуют **оба** файла: `doc.txt` и `doc.txt (конфликт, ...)`;
- ни одна версия не потеряна;
- в интерфейсе оба узла помечены `conflict`;
- выбор основной версии снимает пометку.

**Проверка независимости от часов**: перевести часы на устройстве B на сутки вперёд, повторить сценарий. Ожидаемо: результат тот же — конфликт, а не «B победил».

## 6. Докачка большого файла (SC-002, FR-019…FR-026)

```bash
# 2 ГБ
head -c 2147483648 /dev/zero > /tmp/big.bin

# Начать загрузку и прервать на ~40%
# (Ctrl+C или разрыв соединения)

# Повторить: HEAD должен вернуть смещение
curl -I "$UPLOAD_URL" -H "Authorization: Bearer $ALICE_TOKEN"
# → Upload-Offset: <примерно 40% от 2 ГБ>

# Продолжить с этого смещения
```

**Ожидаемо**: передача продолжается с места прерывания; итоговый хеш совпадает; повторная передача уже принятых байтов не происходит (проверяется по счётчику трафика).

## 7. Поиск и метаданные (SC-007, FR-053…FR-059)

```bash
# Метки и свойства
curl -X POST .../nodes/$FILE/tags -d '{"name":"договор"}'
curl -X POST .../nodes/$FILE/properties -d '{"key":"статус","value":"подписан"}'

# Поиск
curl ".../search?tag=договор"
curl ".../search?q=догов"
curl ".../search?content=подписан"
```

**Ожидаемо**: результаты содержат только доступные пользователю объекты; комбинация условий работает как логическое И; переименованный файл находится по метке.

**Проверка изоляции**: Bob не находит файлы Alice, к которым у него нет доступа, ни по имени, ни по содержимому.

## 8. Квоты (SC-008, FR-070…FR-072)

```bash
# Квота 100 МБ
curl -X PATCH .../admin/users/$ALICE -d '{"quota_bytes":104857600}'

# Загрузить 150 МБ
```

**Ожидаемо**: `413` с указанием остатка и рекомендацией освободить место; файл не появляется; существующие данные не повреждены.

## 9. Администрирование и аудит (SC-009, FR-073…FR-077)

```bash
curl -X PATCH .../admin/users/$BOB -d '{"status":"blocked"}'
curl .../admin/audit?action=user.block
```

**Ожидаемо**: запись в журнале содержит актора, действие, цель и время; сессии Bob завершены; его данные на месте; общие объекты остаются доступны остальным.

## 10. Выгрузка учётной записи (SC-020, FR-098…FR-100)

```bash
curl -X POST .../export -H "Authorization: Bearer $ALICE_TOKEN"
# → 202 { "id": "...", "state": "queued" }

# Дождаться done
curl .../export/$JOB
# → { "state": "done", "download_url": "..." }

curl -fsS "$DOWNLOAD_URL" -o /tmp/export.tar
tar -tf /tmp/export.tar | head
```

**Ожидаемо**: архив содержит все файлы и папки с сохранением структуры; рядом — файл метаданных; зашифрованные папки выгружены в зашифрованном виде.

## 11. Резервное копирование и восстановление (SC-017, SC-018, FR-093…FR-097)

```bash
# 1. Проверить состояние
curl .../admin/backup/status
# → last_backup_at, last_verified_at, last_result

# 2. Учебное восстановление в отдельное пространство
docker compose -f deploy/docker-compose.yml run --rm restore-drill

# 3. Сверить выборку контрольных сумм
```

**Ожидаемо**: восстановление завершается менее чем за 4 часа; выборка файлов совпадает по хешам; при искусственном сбое бэкапа администратор получает уведомление.

## 13. Сквозное шифрование (FR-089…FR-092)

```bash
# Включить шифрование на папке
curl -X POST .../nodes/$FOLDER/e2ee -d '{"recovery_mode":"mnemonic"}'
# → 201 + предупреждение о недоступных возможностях

# Проверить, что поиск по содержимому не находит файлы внутри
curl ".../search?content=<строка из файла>"
# → пусто

# Проверить, что сервер не может отдать открытое содержимое
# (файл скачивается только клиентом, который умеет расшифровать)
```

**Ожидаемо**: предупреждение показано **до** включения; после включения поиск по содержимому и предпросмотр недоступны; отключение шифрования невозможно.
